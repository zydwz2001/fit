# Vibe Fitness Pro

一个面向个人训练复盘的健身记录产品原型。

它把训练记录、身体指标、照片对比和知识沉淀放进同一个工作台里，重点解决个人健身场景里最真实的碎片化问题：训练时不好记、训练后不好复盘、变化数据不好串起来。

## 可交互 Demo

- 在线地址：`https://zydwz2001.github.io/fit/`
- 本地开发：`npm install && npm run dev`
- 生产预览：`npm run build && npm run preview`
- GitHub Pages：主分支通过 GitHub Actions 构建并发布 `dist`，线上版本与 React 源码保持一致

手机可以直接用移动网络打开在线地址，并安装到主屏幕：

- iPhone / iPad：Safari 的“分享” → “添加到主屏幕”
- Android：Chrome 菜单 → “安装应用”或“添加到主屏幕”

Demo 覆盖：

- 训练：今日训练、左右重量、快速填充、移动端排序、训练模板、有氧时长 / 距离 / 强度
- 回顾：月视图与手势切月、历史训练新增 / 编辑 / 删除、动作重量与容量趋势
- 身体：密码入口、体重 / 围度 / BMI、目标线、可缩放趋势图、照片压缩与对比
- 知识库：GFM Markdown、图片与双链、文件夹管理、可配置动作库
- 数据：本地持久化、全量 JSON 导入导出、公斤 / 磅单位切换

## 项目背景

真实的个人健身流程里，记录动作和组数只是第一步，更大的问题是后续如何把训练量、身体变化和知识经验串成连续复盘。传统工具往往只能覆盖其中一段，导致训练、身体数据和笔记彼此割裂。

## 技术方案

- 前端采用 Vite + React + TypeScript，适合快速搭建原型和持续迭代。
- 用 React Context 和 reducer 管理训练、身体和知识三条数据链路。
- 使用 `localStorage` 做本地优先存储，降低原型验证成本。
- 通过 SVG 和 Canvas 处理可缩放图表与照片对比，让身体变化可视化。
- 用 Vitest 和 ESLint 覆盖核心状态逻辑与代码质量检查。

## 实现逻辑

- 训练页支持动作、组数、重量和左右侧数据的快速录入，并在录入时同步计算容量。
- 月视图把训练记录按日期聚合，用于观察部位分布和训练量趋势。
- 身体页把体重、BMI、围度等指标与日期绑定，形成可回看的变化轨迹。
- 照片对比能力把多张身体图放在同一画布中，方便做阶段对照。
- 知识模块用 Markdown、双链和文件夹结构沉淀动作经验和训练反思，形成“训练后复盘”的闭环。

## 开发与校验

```bash
npm install
npm run dev
```

提交前运行：

```bash
npm run check
```

`check` 会依次执行 ESLint、Vitest 和生产构建。GitHub Pages 工作流只在源码推送到 `main` 后发布新版本。

## 设计取舍

- 优先服务训练时的输入效率，而不是先把界面做得很复杂。
- 优先验证“记录 - 复盘 - 沉淀”闭环，而不是一开始追求完整社区或社交能力。
- 以本地数据为中心，适合做个人产品原型和方向验证。

## 当前边界

- 数据仅保存在当前浏览器，没有账号、多设备同步和云端照片存储。
- 身体页密码是本地隐私遮挡，不等同于加密；清理浏览器数据会删除未导出的记录。
- 云同步的产品与技术决策见 [docs/cloud-sync-plan.md](docs/cloud-sync-plan.md)。
